## Экономия лимитов подписки

Разбор сессий (октябрь 2026): ~95% расхода дала одна сессия, которая шла 10 дней с контекстом до 964k, плюс 177 субагентов, половина из них на Opus.

- **Одна сессия — одна задача/этап.** Когда этап (M-веха, фича, багфикс) закончен или контекст перевалил за ~200k, предложи пользователю начать новую сессию. Перед этим запиши статус и следующие шаги в memory (или в docs/план), чтобы новая сессия стартовала с короткого контекста.
- **Не раздувать контекст.** Не читай большие файлы целиком без нужды (используй offset/limit, grep), не выводи длинные логи — фильтруй.
- **Модель субагента указывай всегда явно.** Без `model` субагент наследует Opus сессии — так в M3c–M4b ушли все реализации.
- **Субагенты — на Sonnet.** Исполнение плана, ревью отдельных задач (spec + quality), поиск по коду — `model: "sonnet"`; реализация по плану с готовым кодом — `"haiku"`. Opus — только финальное ревью всей ветки и задачи с глубоким проектированием/сложной отладкой. Ревью отдельной задачи на Opus — не запускать.
- **Меньше субагентов.** Простые задачи (несколько файлов, понятный план) делай сам в текущей сессии, без subagent-driven-development и параллельных агентов. Многоагентные сценарии — только по явной просьбе.
- **Opus — для планирования, Sonnet — для реализации.** Если работа перешла в рутинную фазу (механические правки по плану, тесты), предложи пользователю переключиться на Sonnet (`/model`).

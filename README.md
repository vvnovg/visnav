# VisNav

Android-навигатор, который определяет положение автомобиля по камере, когда GPS пропал или врёт: в тоннелях, среди плотной застройки, при глушении и подмене сигнала. Кадры с камеры сравниваются с заранее загруженной базой уличных снимков с известными координатами. Целевой рынок — Россия и СНГ.

*An Android navigator that localizes a car by matching camera frames against a pre-downloaded database of geotagged street-level imagery when GNSS is lost or spoofed. Research prototype; documentation is in Russian.*

> **Статус: исследовательский прототип.** Этапы M0, M1, M2a и M2c готовы в коде. Полевые испытания ещё не проводились, пользоваться приложением для навигации пока нельзя.

## Как это работает

1. Снимки улиц (сейчас [Mapillary](https://www.mapillary.com), CC BY-SA 4.0) нарезаются на виды, и для каждого вида считается глобальный дескриптор моделью визуального распознавания места (VPR).
2. Дескрипторы района или коридора вдоль маршрута заранее загружаются на телефон.
3. Во время поездки телефон дважды в секунду считает дескриптор кадра и ищет ближайший эталон в окне вокруг последней известной позиции.
4. Фильтр (EKF) объединяет визуальные фиксы, GNSS и датчики телефона (гироскоп, акселерометр) и держит позицию между фиксами.
5. Монитор GNSS по числу спутников, C/N0, усилению приёмника (AGC), скачкам и расхождению с фильтром решает, можно ли доверять GPS. Если нельзя, навигатор переходит в режим «GNSS + камера», «Визуальная навигация» или «Счисление пути».
6. Дальше по плану — привязка к дорожному графу OSM (подробнее в [SPEC.md](docs/SPEC.md)).

## Этапы

| Этап | Что это | Состояние |
|---|---|---|
| **M0** | Бенчмарк VPR-моделей на ПК по своим поездкам. Критерий: Recall@5 ≥ 85 % | Код готов, ждёт записи поездок и токена Mapillary |
| **M1** | Android-прототип: модель на устройстве, поиск по базе района, журнал. Критерий: ≤ 20 м в ≥ 70 % кадров | Код готов, ждёт итогов M0 и полевого теста |
| **M2a** | Фильтр состояния (EKF) с IMU, запись датчиков, replay на ПК с имитацией пропадания GPS. Критерий: P50 ≤ 5 м, P95 ≤ 15 м, дрейф ≤ 3 % | Код готов, ждёт записи поездок |
| M2b | Привязка к дорожному графу OSM | План |
| **M2c** | Монитор GNSS (глушение, подмена) и режимы навигации, фильтр на телефоне. Критерий: подмена и глушение замечаются ≤ 5 с, ложные тревоги ≤ 1 % | Код готов, ждёт поездок, в том числе через зону подмены |
| M3 | Карта, офлайн-маршруты, подсказки | План |
| M4 | Оптимизация, бета-тест | План |

## Инструменты на ПК

Нужны Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
cd research/vpr_bench
uv sync --extra dev
uv run pytest -q
```

- `vpr-bench`:
  - `fetch-refs` — эталоны Mapillary вдоль GPX-треков (токен берётся из переменной окружения `MAPILLARY_TOKEN`);
  - `extract-queries` — кадры поездки, размеченные по GPS, с фильтром подмены и тоннелей;
  - `bench` — сравнение моделей.
- `vpr-m1`:
  - `export-onnx` — экспорт модели для телефона;
  - `quantize-onnx` — квантизация в INT8;
  - `pack-refs` — база района для телефона;
  - `make-parity` — эталон для проверки модели на телефоне;
  - `field-eval` — оценка журнала поездки.
- `vpr-m2`:
  - `replay-eval` — точность и дрейф фильтра по прогону replay;
  - `monitor-eval` — задержка обнаружения подмены и глушения, ложные тревоги, доля распознанной реальной подмены.

Как запускать всё по шагам, описано в [drive-protocol.md](docs/research/drive-protocol.md), [m1-field-test.md](docs/research/m1-field-test.md), [m2a-replay.md](docs/research/m2a-replay.md) и [m2c-monitor.md](docs/research/m2c-monitor.md).

## Android

Нужны JDK 17 и Android SDK (platform 35, build-tools 35.0.0). В `android/local.properties` пропишите путь к SDK (`sdk.dir=…`).

```bash
cd android
./gradlew :core:test :replay:test :app:assembleDebug
```

Если JDK по умолчанию новее 17, укажите его явно: `JAVA_HOME=/путь/к/jdk-17 ./gradlew …`.

Минимальная версия — Android 10 (API 29), только arm64-v8a. Приложению не нужны Google Play Services, а доступа в интернет у него нет вовсе: кадры не покидают устройство. Базу эталонов и модель на телефон нужно положить через `adb push`, как описано в [m1-field-test.md](docs/research/m1-field-test.md).

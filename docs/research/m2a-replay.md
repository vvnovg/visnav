# Replay M2a: фильтр и пропадания GPS

## Запись
Та же поездка и то же приложение, что в протоколе M1 (docs/research/m1-field-test.md), режим «окно по GPS».
Приложение теперь пишет три файла на сессию в `/sdcard/Android/data/io.visnav.app/files/logs/`:
`session-<ms>-gps.jsonl` (кадры), `.sensors.jsonl` (гироскоп и акселерометр 100 Гц, GNSS со скоростью и курсом,
статус спутников) и `.desc` (дескрипторы кадров, ~30 МБ/ч). Изображения не сохраняются.

Требования: телефон жёстко закреплён (дребезг держателя попадает в гироскоп), поездка ≥ 25 минут по городу
вне зоны подмены GPS и без тоннелей — GPS нужен как истинная позиция на всём пути.

## Пропадания
GPS «выключается» программно на replay. Стандартный набор для сессии ≥ 25 мин (секунды от начала):
`--outage 120:30 --outage 300:60 --outage 600:120 --outage 900:300`.

Если в отчёте стоит «⚠️ нет данных для проверки», значит в окнах пропаданий не нашлось кадров в движении с GPS — сдвиньте окна или выберите другую сессию.

```bash
cd /Users/vvnovg/navigator/android
export JAVA_HOME="$(brew --prefix openjdk@17)/libexec/openjdk.jdk/Contents/Home"
S=/Users/vvnovg/navigator/research/vpr_bench/data/m1/logs/session-<ms>-gps
R=/Users/vvnovg/navigator/research/vpr_bench/data/m1/bundle
O="--outage 120:30 --outage 300:60 --outage 600:120 --outage 900:300"
./gradlew -q :replay:run --args="--session $S --refpack $R --out $S.replay-visual.jsonl $O"
./gradlew -q :replay:run --args="--session $S --refpack $R --out $S.replay-dr.jsonl $O --no-visual"
cd /Users/vvnovg/navigator/research/vpr_bench
uv run vpr-m2 replay-eval --traj $S.replay-visual.jsonl --log $S.jsonl --out data/m2a/replay-visual.md
uv run vpr-m2 replay-eval --traj $S.replay-dr.jsonl --log $S.jsonl --out data/m2a/replay-dr.md
```

## Первый прогон — проверка перед полным набором
После самой первой поездки прогоните replay один раз (можно даже без `--outage`) и проверьте
вывод `:replay:run` и получившиеся отчёты, прежде чем записывать «Итоги» ниже. Отчёты теперь всегда
печатают долю visState и доли ZUPT по всей траектории (не только по пропаданиям) — они видны в
`replay-visual.md`/`replay-dr.md` даже если пропаданий не было и «⚠️ нет данных для проверки»:
- доля кадров `no_desc` в отчёте («визуальные фиксации: … no_desc V %») ≈ 0 % — иначе `.desc`
  и `.jsonl` не совпадают по времени или refpack не тот;
- `clock drift max N ms`, напечатанный `:replay:run`, ≤ 1000 мс — если больше, `:replay:run`
  дополнительно печатает предупреждение в stderr (прогон при этом не останавливается: это часы
  датчиков (`clk` в `.sensors.jsonl`), а не факт того, что запись непригодна);
- `:replay:run` не завершился с ошибкой первой метки датчика — проверка «первая метка **гироскопа
  или акселерометра** в пределах 5 с от started_ms» сама останавливает прогон с кодом 2, если не
  пройдена. Она намеренно смотрит только на IMU: метка кадра (`frame`/`frame_t_ms` в
  `.sensors.jsonl`) — это то же настенное время, что и `t_ms` в `.jsonl`, без конвертации через
  часы датчиков, так что её нельзя сравнивать с этой проверкой «в лоб»;
- доли «ложная стоянка, %» / «пропущенная стоянка, %» в таблице replay-dr.md (и в строке «ZUPT по
  всей траектории» над таблицей) разумны (не 100 %/0 % на всём маршруте — иначе StationaryDetector
  рассинхронизирован с реальной ездой);
- доли visState (`ok`/`gated`/`below`/`empty_window`/`no_desc`) в replay-visual.md выглядят
  правдоподобно для местности (в основном `ok`, не сплошь `gated`/`below`).

Только после того как эта проверка прошла, катайте полный набор пропаданий и переносите таблицы в «Итоги».

## Критерий M2a
- [ ] NFR-1 на replay с визуальными фиксациями: P50 ≤ 5 м, P95 ≤ 15 м — факт: …
- [ ] NFR-5 на replay без визуальных фиксаций: дрейф ≤ 3 % пути, считается по пропаданиям
      ≥ 1 км пройденного пути (более короткие остаются в таблице как ориентировочные,
      отмечены «(ориентир.)», и не входят в вердикт) — факт: …

  Известное ограничение (owner decision, 2026-09-27): счисление пути сейчас не использует модель
  продольного ускорения по GPS (обучение направления «вперёд» телефона по скорости/курсу GPS,
  интегрирование со смещением на время пропадания) — это отдельный небольшой план, будет сделан
  после первой записанной поездки. До этого NFR-5 на реальных данных, скорее всего, не пройдёт —
  это ожидаемо и не блокирует M2a, а фиксирует базовую линию для последующего плана.

## Что передаётся в M2b/M2c
- Эпизоды, где фильтр держался на правильной улице / съезжал на соседнюю (вход для привязки к дорогам, M2b).
- Поведение статуса спутников (`gnss` в .sensors.jsonl) в местах подмены и глушения (вход для монитора GNSS, M2c).

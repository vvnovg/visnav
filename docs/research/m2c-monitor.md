# M2c: монитор GNSS и режимы навигации

## Что пишет приложение

Помимо файлов M2a (`.jsonl`, `.sensors.jsonl`, `.desc`) приложение пишет `.fusion.jsonl` — оценку фильтра на телефоне по каждому кадру. В каждой строке:
- позиция;
- радиус доверия;
- режим;
- состояние GNSS;
- причины этого состояния.

Изменения в `.sensors.jsonl`:
- у событий `gnss` появились разброс и максимум C/N0, а также число спутников по системам (GPS, ГЛОНАСС, Galileo, BeiDou);
- добавились события `agc` — уровень усиления приёмника. Они есть не на всех телефонах.

На экране показывается режим с цветом и «±N м»:
- зелёный — `GNSS` и «GNSS + камера»;
- синий — «Визуальная навигация»;
- оранжевый — «Счисление пути».

Если сигнал GNSS не в норме, ниже выводятся причины.

На телефоне события подаются в фильтр с задержкой 1,5 с, строго по времени, так же как в replay. Поэтому индикатор режима отстаёт на 1,5–2 с, зато `.fusion.jsonl` можно сравнивать с replay той же сессии. При остановке записи в статусе показывается, сколько событий пришло слишком поздно и сколько отброшено при переполнении очереди. В нормальной поездке оба числа должны быть нулевыми.

## 1. Подмешивание на чистых поездках (replay)

Берутся поездки M2a, проходящие вне зоны подмены. Для сессии длиной от 25 минут используется такой набор окон:

```
--spoof 300:60:0:300 --spoof 900:60:500:0 --spoof 1200:120:0:150:60 --jam 600:60
```

Формат: `--spoof НАЧАЛО_С:ДЛИНА_С:ВОСТОК_М:СЕВЕР_М[:РАМПА_С]`, `--jam НАЧАЛО_С:ДЛИНА_С`. Третье окно подмены — медленный увод: смещение нарастает до 150 м за 60 с.

```bash
cd /Users/vvnovg/navigator/android
export JAVA_HOME="$(brew --prefix openjdk@17)/libexec/openjdk.jdk/Contents/Home"
S=/Users/vvnovg/navigator/research/vpr_bench/data/m1/logs/session-<ms>-gps
R=/Users/vvnovg/navigator/research/vpr_bench/data/m1/bundle
I="--spoof 300:60:0:300 --spoof 900:60:500:0 --spoof 1200:120:0:150:60 --jam 600:60"
./gradlew -q :replay:run --args="--session $S --refpack $R --out $S.m2c.jsonl $I"
./gradlew -q :replay:run --args="--session $S --refpack $R --out $S.m2c-off.jsonl $I --no-monitor"
cd /Users/vvnovg/navigator/research/vpr_bench
uv run vpr-m2 monitor-eval --traj $S.m2c.jsonl --log $S.jsonl --out data/m2c/monitor.md
uv run vpr-m2 monitor-eval --traj $S.m2c-off.jsonl --log $S.jsonl --out data/m2c/monitor-off.md
```

Что считает `monitor-eval`:
- **Задержка.** Для окна подмены — от начала окна до первой строки с `untrusted`. Для окна глушения — до первой строки с режимом не `gnss`.
- **Ложное `UNTRUSTED`.** Доля таких строк в чистом времени: вне всех окон, после первых 60 с, в движении от 2 м/с. Секунды реальной подмены из журнала GPS (от 1 с до и до 15 с после каждой метки) в чистое время не входят. 15 с покрывают возврат доверия к GNSS: 10 с подтверждений и 2 с гистерезиса.
- **P95 ошибки в окнах подмены** относительно GPS после фильтра качества трека.

## 2. Реальная зона подмены

Нужна одна поездка по маршруту, который проходит по краю зоны подмены в центре (Бульварное кольцо, набережные у Кремля) и возвращается за Садовое кольцо. Ехать как обычно, по правилам; телефон пишет всё в обычном режиме.

`monitor-eval` сам размечает подмену по журналу GPS: это точки, которые удаляет фильтр качества трека M0. Затем он считает, какую долю этих секунд распознал монитор. Истинной позиции внутри зоны нет, поэтому точность там не оценивается.

```bash
uv run vpr-m2 monitor-eval --traj <сессия>.fusion.jsonl --log <сессия>.jsonl --out data/m2c/real-spoof.md
```

`.fusion.jsonl` — это вывод фильтра на телефоне в реальном времени. Для сравнения стоит прогнать replay той же сессии (`--out <сессия>.m2c.jsonl`, без окон) и оценить оба файла.

## Известные ограничения (по синтетике, до полевых данных)

- **Медленный увод без признаков в C/N0 обнаруживается поздно.** При уводе на 50 м за 60 с, когда C/N0 спутников не выдаёт подмену, монитор срабатывает только через 52 с по расхождению с фильтром. Ошибка за это время доходит до 20 м. Если увод сопровождается одинаковым C/N0 на всех спутниках, монитор срабатывает через 2 с. Синтетическая подмена сдвигает только координаты, а скорость и курс оставляет честными. Настоящий спуфер подделывает и их, поэтому в реальности медленный увод может оставаться незамеченным ещё дольше.
- **Без камеры GNSS не возвращается после срабатывания по расхождению с фильтром** (`INNOVATION`). Доверие возвращается только по подтверждению: визуальный фикс рядом с GNSS или фильтр с σ ≤ 30 м. Таймера нет. Если камера не даёт фиксов, навигатор останется в режиме «Счисление пути» до конца сессии. Решение за владельцем после полевых данных.
- **Скорость реакции.** При глушении режим `GNSS` уходит примерно через 4,5 с после пропажи сигнала (≈ 5,5 с после последнего фикса). Режим «Визуальная навигация» или «Счисление пути» наступает примерно через 11,5 с.
- **Переинициализация фильтра** по согласию визуального фикса и GNSS при настройках по умолчанию почти не срабатывает: раньше её доверие возвращает согласие фильтра.

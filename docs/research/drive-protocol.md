# Протокол записи поездок для датасета M0

## Оборудование
- Смартфон на держателе у лобового стекла, камера смотрит вперёд, капот занимает ≤ 20 % кадра.
  Либо видеорегистратор, дающий файл MP4.
- Частоту кадров видео зафиксировать, если приложение камеры это позволяет
  (например, 30 fps fixed, а не автоматический диапазон) — так проще проверять
  синхронизацию и меньше дрейф между временем контейнера и GPX. Разрешение
  записать в `sessions.csv` (см. ниже).
- GPS-трек пишется на том же смартфоне приложением GPSLogger for Android
  (формат GPX, интервал 1 с, «только GPS»). Для M0 достаточно обычного GPS
  при открытом небе: точность ~3–5 м заметно лучше порога 25 м. RTK — в M2.

## Геометрия камеры

Эталонные виды из панорамы нарезаются с полем зрения (FOV), которое должно
соответствовать реальной камере, иначе масштаб объектов в кадре запроса и
эталона не совпадёт. HFOV измеряется один раз на каждый способ крепления
телефона (держатель, регистратор):

1. Поставить телефон/регистратор на штатное место, включить запись видео с
   тем же разрешением, что и в поездках.
2. Направить камеру на стену на известном расстоянии `D` (например, 2 м).
3. Отметить на стене точки, соответствующие левому и правому краю кадра
   (по live-preview или по стоп-кадру), измерить расстояние между ними `W`.
4. Посчитать горизонтальный угол обзора: `HFOV = 2 · atan(W / (2 · D))`.

Записать в `sessions.csv` для каждой сессии: `hfov_deg` (результат шага 4),
`width`, `height` — разрешение видео в пикселях. Эти три числа передаются в
`fetch-refs --fov --width --height`, чтобы виды из панорамы совпадали по
геометрии с кадрами запроса.

## Синхронизация времени видео и трека

Нужна точность до долей секунды: при типичной скорости поездки 40–60 км/ч
ошибка в 1 с — это 10–17 м смещения истинной позиции, что уже сопоставимо с
порогом проверки сессии (10 м, см. ниже) и минимально допустимым запасом до
порога совпадения (25 м).

1. Включить запись видео.
2. Первые 3 секунды снимать миллисекундные часы — например, веб-страницу с
   часами, показывающими миллисекунды (`time.is` показывает только секунды и
   не подходит; нужен секундомер/часы с мс, например `stopwatch.rocks` или
   аналог), на экране второго телефона.
3. По первому кадру определить время начала видео с точностью ±0.1 с и
   записать его в ISO-формате с миллисекундами и часовым поясом в
   `sessions.csv` (`video_start_iso`), например `2026-09-20T10:00:03.250+03:00`.
4. Перекрёстная проверка: момент, когда машина трогается с места (видно на
   видео), должен совпадать с моментом, когда скорость по GPX превышает
   2 м/с, с точностью ±0.5 с. Если расхождение больше — поправить
   `video_start_iso`.

## Выбор города
Покрытие Mapillary в России и СНГ неравномерное. До записи поездок откройте
mapillary.com/app и выберите город и районы, где снимки есть на большинстве
улиц будущих маршрутов (зелёные линии последовательностей и точки панорам).
Предпочтительны снимки не старше 3–4 лет. Если подходящего покрытия нет ни в
одном доступном городе — это сам по себе результат M0: зафиксировать его в
итогах и ускорить переговоры с Яндексом.

### Москва (город M0)
- **Подмена GPS в центре.** В районе Кремля и в пределах примерно Бульварного
  кольца телефоны регулярно получают ложные координаты (позиция «прыгает» в
  аэропорты или соседние районы). В таких местах GPS-трек нельзя использовать как
  истинную позицию. Маршруты S1–S4 прокладывать вне этой зоны; «центр» для S1 —
  между Садовым кольцом и ТТК.
- **Тоннели** (Лефортовский, Северо-Западный, тоннели ТТК и Садового кольца): в
  них GPS пропадает, а трек в GPX прямой линией соединяет вход и выход. Кадры из
  тоннелей в M0 не используются — их отбрасывает фильтр качества трека.
- **Проверка трека после поездки.** Открыть GPX на карте (например, в gpx.studio)
  и убедиться, что нет скачков на сотни метров и «телепортаций». Участки со
  скачками вырезать или пометить в `notes` в `sessions.csv`.
- **Покрытие Mapillary.** Перед записью проверить на mapillary.com/app районы
  между Садовым кольцом и ТТК и 2–3 спальных района; выбрать для S1/S2 улицы,
  где есть снимки.

## Маршруты (минимум для M0)
| Сессия | Условия | Длина | Требование |
|---|---|---|---|
| S1 | день, город, центр | ≥ 15 км | улицы, где в Mapillary есть снимки (проверить на mapillary.com/app) |
| S2 | день, спальный район | ≥ 10 км | то же |
| S3 | вечер / ночь | ≥ 10 км | повтор части S1 |
| S4 | дождь или мокрая дорога | ≥ 10 км | повтор части S1 или S2 |

Итого ≥ 45 км. Из них после нарезки с шагом 1 с и отбрасывания стоянок должно получиться ≥ 2000 кадров-запросов.

## Раскладка файлов
```
research/vpr_bench/data/drives/<session>/video.mp4
research/vpr_bench/data/drives/<session>/track.gpx
research/vpr_bench/data/drives/sessions.csv   # session,video_start_iso,hfov_deg,width,height,conditions,notes
```

`video_start_iso` — с миллисекундами и часовым поясом (`extract-queries`
отклоняет значения без часового пояса).

## Проверка сессии
```bash
uv run vpr-bench extract-queries --video data/drives/S1/video.mp4 --gpx data/drives/S1/track.gpx \
  --video-start <video_start_iso из sessions.csv> --every 1 --out data/queries/S1
```

Выборочно открыть 5 кадров из data/queries/S1/images и сверить место на карте
по координатам из queries.csv. Расхождение > 10 м означает ошибку синхронизации: поправить video_start_iso.

## Команды для полного прогона

Сбор эталонов вдоль всех треков одним запросом (коридор вокруг GPX,
геометрия вида — под камеру запроса; здесь `W×H` — с тем же соотношением
сторон, что и у видео запросов, например 640×360 для 16:9):

```bash
uv run vpr-bench fetch-refs --gpx data/drives/S1/track.gpx --gpx data/drives/S2/track.gpx \
  --gpx data/drives/S3/track.gpx --gpx data/drives/S4/track.gpx \
  --buffer-m 600 --fov <hfov_deg> --width <W> --height <H> --out data/refs
```

Нарезка запросов на каждую сессию отдельно (как в разделе «Проверка
сессии», с миллисекундным `--video-start`):

```bash
uv run vpr-bench extract-queries --video data/drives/S1/video.mp4 --gpx data/drives/S1/track.gpx \
  --video-start <video_start_iso> --every 1 --out data/queries/S1
```
(повторить для S2, S3, S4).

Один прогон бенчмарка по всем сессиям сразу:

```bash
uv run vpr-bench bench --refs data/refs/refs.csv \
  --queries S1=data/queries/S1/queries.csv --queries S2=data/queries/S2/queries.csv \
  --queries S3=data/queries/S3/queries.csv --queries S4=data/queries/S4/queries.csv \
  --pool S1,S2 --models cosplace-r50,eigenplaces-r50,salad-dinov2,boq-dinov2 --out data/results
```

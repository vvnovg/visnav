# M3c: пакет поездки

Поездку, которая ещё не проехана, можно подготовить на ПК и положить на телефон одним каталогом. На телефоне может лежать несколько поездок, нужная выбирается на вкладке «Навигация».

## Что нужно
- Выгрузка OSM (`data/osm/moscow.osm.pbf`) — как в M2b.
- Тайлы planetiler (`data/m3b/moscow.mbtiles`) и шрифты (`data/osm/noto-sans.zip`) — как в M3b (`docs/research/m3b-map.md`).
- Модель для телефона: `vpr-m1 export-onnx` и `quantize-onnx`, см. `docs/research/m1-field-test.md`. Все поездки на телефоне используют одну модель.
- Токен Mapillary в переменной окружения `MAPILLARY_TOKEN` — для `fetch-refs`.

## 1. Граф города (раз в месяц)
```bash
cd /Users/vvnovg/navigator/research/vpr_bench
uv run vpr-m2 pack-roads --pbf data/osm/moscow.osm.pbf --bbox 37.30,55.55,37.95,55.95 --out data/m3c/city-roads
```
- Граф всего города нужен только для маршрута на ПК, на телефон он не кладётся.
- Краёв коридора в этом режиме нет: линии, пересекающие границу `--bbox`, читаются целиком.

## 2. Маршрут
```bash
cd /Users/vvnovg/navigator/android
export JAVA_HOME="$(brew --prefix openjdk@17)/libexec/openjdk.jdk/Contents/Home"
./gradlew -q :replay:run --args="trip-plan --roads /Users/vvnovg/navigator/research/vpr_bench/data/m3c/city-roads \
  --from 55.7520,37.6175 --via 55.7600,37.6400 --to 55.7700,37.5900 \
  --out /Users/vvnovg/navigator/research/vpr_bench/data/m3c/work/route.gpx"
```
- Маршрут строит тот же маршрутизатор, что и на телефоне.
- `--via` можно повторять; каждая следующая нога продолжает курс предыдущей, поэтому на промежуточной точке маршрут не разворачивается «на месте».
- Выход — GPX с точками не реже чем через 25 м и временем в каждой точке.
- Команда печатает длину и оценку времени. Оценка включает штрафы за повороты, поэтому она завышена.
- Код 2 — точка не привязалась к дороге или маршрут не найден.
- JVM запускается с `-Xmx4g`: граф Москвы большой.

## 3. Эталоны
```bash
cd /Users/vvnovg/navigator/research/vpr_bench
uv run vpr-bench fetch-refs --gpx data/m3c/work/route.gpx --buffer-m 300 \
  --fov <hfov_deg> --width <W> --height <H> --out data/m3c/work/refs
```
Параметры `--fov`, `--width` и `--height` — как в `docs/research/drive-protocol.md`.

## 4. Пакет
```bash
uv run vpr-m3 pack-trip --route data/m3c/work/route.gpx --name work --dest-name "Работа" \
  --refs data/m3c/work/refs/refs.csv --onnx data/m1/model-int8.onnx \
  --pbf data/osm/moscow.osm.pbf --mbtiles data/m3b/moscow.mbtiles --fonts-zip data/osm/noto-sans.zip \
  --out data/m3c/refpack
```
Результат:
```
data/m3c/refpack/model.onnx                      общая модель
data/m3c/refpack/trips/work/refpack.bin|json     эталоны, ±300 м
data/m3c/refpack/trips/work/roadpack.bin|json    граф дорог v3, ±300 м, края коридора отмечены
data/m3c/refpack/trips/work/map/                 карта, ±500 м
data/m3c/refpack/trips/work/route.json           финиш — конец маршрута
data/m3c/refpack/trips/work/trip.json            сводка: длина, размеры, МБ на 100 км
```
- **Печать.** Команда печатает размеры частей и МБ на 100 км. Если больше 50 (цель NFR-8), выводится предупреждение.
- **Сборка безопасна.** Пакет собирается во временном каталоге `trips/.work.tmp` и заменяет поездку, только когда всё готово. Если поездка уже есть, нужен `--force`. Старая поездка не теряется ни при ошибке, ни при обрыве: прерванная замена восстанавливается при следующем запуске.
- **Одна модель.**
  - Модель в корне — образец. Пакет с другой моделью отклоняется до тяжёлых шагов.
  - Если модели в корне нет, новая модель сравнивается с моделями других поездок (заменяемая поездка не учитывается).
- **Буферы:** `--refs-buffer-m`, `--roads-buffer-m`, `--map-buffer-m` (по умолчанию 300, 300, 500).

## 5. Телефон
```bash
adb push data/m3c/refpack/. /sdcard/Android/data/io.visnav.app/files/refpack/
```
- Над кнопкой «Старт» на вкладке «Навигация» показывается «Поездка: <имя>». Если поездок несколько, это выпадающий список; во время записи и загрузки выбор недоступен.
- Выбор запоминается. При смене поездки база, модель и граф перезагружаются, карта берётся из каталога поездки.
- Новая поездка, положенная через adb при открытом приложении, появляется в списке при входе на вкладку «Навигация».
- Имя поездки пишется в заголовок журнала сессии (`trip`).
- Удалить поездку: `adb shell rm -r /sdcard/Android/data/io.visnav.app/files/refpack/trips/<имя>`.
- Если каталога `trips/` нет, работает старая раскладка M1–M3b (`refpack/` с базой, графом и картой).

## Как это устроено
- **Края коридора.**
  - Узел графа вне коридора — край: дорога за ним обрезана. Маршрутизатор у края не разворачивается, разворот возможен только в настоящем тупике.
  - Если машина едет к краю, а цель позади, маршрут начинается против курса, и сразу звучит «Развернитесь».
  - На разделённой дороге, упирающейся в край, маршрута нет («Маршрут не найден»), пока водитель не развернётся сам: внутри коридора законного пути назад нет.
- **Модель.** Модель берётся из каталога поездки, если она там есть, иначе — общая из корня.
- **Проверка parity** (эталон в корне) выполняется только для общей модели.

## Ограничения
- **Промежуточные точки задают только коридор.** На телефоне маршрут строится к финишу внутри коридора и может срезать мимо via.
- **Только внутри коридора** (±300 м вокруг маршрута), как в M3a.
- **Без интернета:** пакеты кладутся через adb.
- **Не входит в M3c:**
  - отчёт о покрытии эталонами и подсветка участков без эталонов;
  - проверка целостности файлов пакета.
- **Коридор считается по точкам трека**, а не по отрезкам. Для GPX от `trip-plan` (шаг ≤ 25 м) это незаметно; редкий рисованный GPX даст «цепочку кругов».

## Что проверить в поездке
- Маршрут на телефоне совпадает с маршрутом `trip-plan`.
- У края коридора нет предложений развернуться; при выезде к краю звучит «Развернитесь».
- Переключение поездок до старта: карта, маршрут и статус меняются.
- Размер пакета на 100 км.

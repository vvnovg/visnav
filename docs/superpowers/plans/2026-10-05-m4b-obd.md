# M4b: скорость из машины через OBD-II — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** скорость автомобиля с ELM327 (Bluetooth Classic и BLE) записывается в журнал, идёт в фильтр измерением скорости с поправкой спидометра и ловит подмену GNSS по расхождению скоростей. В replay её можно включить и выключить, на ПК — отчёт `obd-eval`.

**Architecture:**
- **`:core`:**
  - `ObdSpeedEvent` и его строка в `.sensors.jsonl`;
  - разбор ответов `Elm327` и диалог `ElmSession` над абстрактным `ElmChannel`;
  - в `Localizer` — измерение скорости и `k`;
  - в `GnssMonitor` — `SPEED_MISMATCH`.
- **`:app`:** каналы `SppChannel` и `BleChannel`, `ObdClient`, разрешения Bluetooth, блок «OBD» на «Отладке».
- **`:replay`:** события OBD и `--no-obd`.
- **Python:** `vpr-m2 obd-eval`.

**Tech Stack:** Kotlin 2.1 (`:core` JVM, `:app` Android Bluetooth Classic и BLE, `:replay`), Python 3.11+, JUnit, pytest.

**Спецификация:** `docs/superpowers/specs/2026-10-05-m4b-obd-design.md`.

## Global Constraints

- **Решения владельца (2026-10-05):**
  - ELM327 по Bluetooth Classic (SPP) и по BLE через общий слой;
  - скорость OBD — измерение в фильтре и проверка подмены GNSS.
- **Строка `.sensors.jsonl`:** `{"t":<мс>,"k":"obd","kmh":<int>,"rtt_ms":<double>}`. Время `t` — `отправка + RTT/2` в шкале датчиков (`SensorRecorder.offsetMs + elapsedRealtimeNanos/1e6`). Контракт аддитивный, остальные строки не меняются.
- **ELM327:**
  - инициализация `ATZ`, `ATE0`, `ATL0`, `ATS0`, `ATH0`, `ATSP0`, `0100`;
  - опрос `010D`;
  - конец ответа — `>`; таймаут ответа 1000 мс (`ATZ` — 3000 мс, `0100` — 10 000 мс);
  - интервал опроса не меньше 200 мс;
  - 5 ошибок подряд → переподключение с паузами 2/5/10/10… с.
- **SPP UUID:** `00001101-0000-1000-8000-00805F9B34FB`.
- **BLE:**
  - сервис `0000FFF0-…`, уведомления `FFF1`, запись `FFF2`;
  - запасной — Nordic UART `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`, запись `…0002`, уведомления `…0003`;
  - запись кусками ≤ 20 байт;
  - имена для поиска: `OBD`, `OBDII`, `V-LINK`, `IOS-Vlink`, `Vgate`, `OBDLink` (без учёта регистра, вхождение).
- **Фильтр:**
  - `σ = max(0.3, 0.5/3.6 + 0.01·v)` м/с;
  - `k`:
    - EMA с постоянной 60 с;
    - обучается только при здоровье `GOOD`, `v_gnss ≥ 5 м/с` и OBD не старше 500 мс;
    - ограничен [0.9, 1.1], начальное значение `1/1.03`;
  - `kmh == 0` при `!stationary` — измерение не применяется;
  - `kmh == 0` при `stationary` — `updateSpeed(0, 0.05)`.
- **`SPEED_MISMATCH`** (входит в `UNTRUSTED_REASONS`; OBD не старше 1 с):
  - (a) `|v_gps − v_obd| > max(2, 0.1·v_obd)` подряд 5 с;
  - (b) за скользящие 30 с `|Σv_gps·dt − Σv_obd·dt| > max(15, 0.05·Σv_obd·dt)` м;
  - (c) `v_obd < 0.3` и `v_gps > 1.5` подряд 3 с.

  Причина держится 10 с после последнего нарушения. Подпись — «скорость GPS ≠ машина».
- **Разрешения:**
  - Android 12+: `BLUETOOTH_CONNECT`, `BLUETOOTH_SCAN` (`android:usesPermissionFlags="neverForLocation"`, `tools:targetApi="s"`);
  - `BLUETOOTH` и `BLUETOOTH_ADMIN` с `android:maxSdkVersion="30"`.

  Сетевые разрешения по-прежнему удалены. Новых зависимостей нет.
- **Настройки в `SharedPreferences "visnav"`:** `obd_kind` (`off`/`spp`/`ble`, по умолчанию `off`), `obd_addr`, `obd_name`.
- **Сборка и тесты:**
  - Gradle: `cd /Users/vvnovg/navigator/android && JAVA_HOME="$(brew --prefix openjdk@17)/libexec/openjdk.jdk/Contents/Home" ./gradlew …`
  - Python: `cd /Users/vvnovg/navigator/research/vpr_bench && uv run pytest -q`

### Task 2: диалог ELM327 над абстрактным каналом (`:core`)

**Files:**
- Create: `android/core/src/main/kotlin/io/visnav/core/ElmSession.kt`
- Test: `ElmSessionTest.kt`

**Interfaces:**

```kotlin
interface ElmChannel {
    fun write(cmd: String)                 // добавляет "\r"
    /** Ответ до ">" включительно или null по таймауту. */
    fun readUntilPrompt(timeoutMs: Long): String?
    fun close()
}
enum class ElmState { CONNECTING, INIT, SEARCHING, POLLING, NO_DATA, ERROR, RECONNECT_WAIT, STOPPED }

class ElmSession(
    private val open: () -> ElmChannel,                 // бросает при неудаче подключения
    private val nowMs: () -> Double,                    // шкала датчиков (настенное время)
    private val sleep: (Long) -> Unit,
    private val onSpeed: (ObdSpeedEvent) -> Unit,
    private val onState: (ElmState, String?) -> Unit,
    private val minIntervalMs: Long = 200,
) {
    /** Блокирующий цикл до stop(): подключение, INIT, опрос, переподключение. */
    fun run()
    fun stop()
}
```

Правила:
- **Подключение:**
  - `open()`;
  - `INIT`: команды `Elm327.INIT`, таймауты как в Global Constraints;
  - на `0100` ответ `SEARCHING...` ждётся до 10 с, затем `UNABLE TO CONNECT` / `NO DATA` → состояние `NO_DATA` и повтор `0100` через 5 с.
- **Опрос:**
  - `POLLING`: `t0 = nowMs()`, `write("010D")`, ответ, `rtt = nowMs() − t0`;
  - `parseSpeed` → `onSpeed(ObdSpeedEvent(t0 + rtt/2, kmh, rtt))`;
  - пауза до `minIntervalMs` от `t0`.
- **Ошибки:** ошибка или таймаут → счётчик; 5 подряд → `close()`, `RECONNECT_WAIT` с паузами 2000/5000/10000/10000… мс; успешный ответ сбрасывает счётчик и паузу.
- **Остановка:** `stop()` прерывает цикл (флаг плюс `close()`), состояние `STOPPED`.

- [ ] **Step 1: Тесты** с поддельным каналом (очередь ответов, учёт записанных команд, поддельные часы и `sleep`):
  - **Нормальный опрос:**
    - INIT в правильном порядке;
    - три ответа `41 0D 3C` → три события 60 км/ч;
    - `t` = `t0 + rtt/2`;
    - пауза `minIntervalMs` соблюдается (по поддельным часам).
  - **`SEARCHING...` → `41 00 …`:** переход в `POLLING`.
  - **`NO DATA` на 0100:** состояние `NO_DATA`, повтор через 5 с.
  - **5 таймаутов подряд:** `close()`, `RECONNECT_WAIT`, пауза 2000; повторное подключение; после успеха пауза сбрасывается.
  - **`open()` бросает:** паузы растут 2000 → 5000 → 10000.
  - **`stop()`** из другого потока завершает `run()` не позже чем через один таймаут.
- [ ] **Step 2–4:** RED → реализация → GREEN.
- [ ] **Step 5: Commit** — `feat(core): ELM327 session over an abstract channel (init, polling, reconnect)`

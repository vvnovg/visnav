# M3c: пакет коридора для поездки — дизайн

Дата: 2026-10-04. Решения владельца — в этом документе (ответы на вопросы перед планом).

## Цель
Поездку, которая ещё не проехана, можно подготовить на ПК одной цепочкой команд и положить на телефон. На телефоне может лежать несколько поездок, нужная выбирается в приложении. Маршрутизатор не разворачивается у края коридора.

## Решения владельца (2026-10-04)
- **Коридор** — маршрут на ПК нашим A*: тот же `Router` из `:core`, что и на телефоне.
- **На телефоне** — несколько поездок в `files/refpack/trips/<имя>/`, выбор на вкладке «Навигация». Старая раскладка `refpack/` работает как раньше.
- **Края коридора** отмечаются в графе дорог (roadpack v3), у них разворот запрещён.
- **Не входит в M3c:**
  - отчёт о покрытии эталонами и подсветка участков на карте;
  - проверка целостности пакета (SHA-256 файлов).

  Остаются только проверки, которые уже есть: модель против эталонов (размер входа, размерность дескриптора) и вывод размера на 100 км.

## Поток данных
1. **Граф города (ПК, раз в месяц):**
   `vpr-m2 pack-roads --pbf moscow.osm.pbf --bbox 37.30,55.55,37.95,55.95 --out data/m3c/city-roads`.
   Граф всего города нужен только для маршрута на ПК, на телефон он не кладётся.
2. **Маршрут (ПК, JVM):**
   `./gradlew :replay:run --args="trip-plan --roads data/m3c/city-roads --from LAT,LON --to LAT,LON [--via LAT,LON]... --out route.gpx"`.
   - На выходе GPX: точки не реже чем через 25 м, у каждой точки время (на 10 м/с) — его требует `parse_gpx`.
   - Печатает длину и оценку времени.
   - Код возврата 2, если старт, финиш или промежуточная точка не привязались к дороге или маршрут не найден.
3. **Эталоны (ПК, владелец, сеть и токен):** `vpr-bench fetch-refs --gpx route.gpx --buffer-m 300 --out data/m3c/refs-<имя>`.
4. **Пакет (ПК):**
   `vpr-m3 pack-trip --route route.gpx --name <имя> --refs …/refs.csv --onnx model.onnx --pbf moscow.osm.pbf --mbtiles moscow.mbtiles --fonts-zip noto-sans.zip --out data/m3c/refpack`.

   Раскладка результата:
   ```
   data/m3c/refpack/model.onnx                 общая для всех поездок
   data/m3c/refpack/trips/<имя>/refpack.bin|json
   data/m3c/refpack/trips/<имя>/roadpack.bin|json   v3, ±300 м, края отмечены
   data/m3c/refpack/trips/<имя>/map/                ±500 м
   data/m3c/refpack/trips/<имя>/route.json          финиш = последняя точка маршрута
   data/m3c/refpack/trips/<имя>/trip.json           сводка и размеры
   ```
5. **Телефон:** `adb push data/m3c/refpack/. /sdcard/Android/data/io.visnav.app/files/refpack/`.

## Компоненты
- **roadpack v3.**
  - Формат: v2 + `boundaryCount u32` + `boundary i32[boundaryCount]` (индексы узлов, по возрастанию, без повторов).
  - Python пишет v3 по умолчанию; Kotlin и Python читают v1–v3.
  - Узел — край коридора, если он в графе, но вне коридора: это внешний конец сохранённого отрезка, данные вокруг него неполные. Изменено после ревью Task 1: правило «у узла есть отброшенный отрезок» пропускало узлы, где дорога продолжается только по линии, целиком лежащей вне bbox чтения.
  - Настоящий тупик внутри коридора краем не считается. Тупик сразу за коридором тоже станет краем — это безвредно.
  - В режиме `--bbox` обрезки по коридору нет, список краёв пуст.
- **Router.** У узла-края разворот на том же ребре запрещён, как у узла степени > 1. Разворот в настоящем тупике — как в M3a (штраф 120 с).
- **`trip-plan`** — подкоманда `:replay` (`Main.kt` передаёт её в `TripPlan.kt`).
  - Ноги «старт → via → … → финиш» строятся по одной, каждая следующая — от проекции конца предыдущей.
  - Курс на старте неизвестен (`headingRad = null`).
- **`pack-trip`** — Python-оркестратор поверх существующих `pack-refs`, `pack-roads`, `pack-map`.
  - Имя поездки: `[A-Za-z0-9_-]{1,40}`.
  - Существующий каталог поездки — ошибка, если не передан `--force`.
  - Модель переносится в корень `--out`. Если там уже лежит другая модель (SHA-256 не совпадает), это ошибка: все поездки на телефоне используют одну модель.
- **Приложение:**
  - `TripLayout` (чистая логика на `File`, тесты на JVM): список поездок, каталог данных и файл модели для выбранной поездки или старой раскладки.
  - `BundleLoader.load(dataDir, modelFile)`.
  - `M1Controller.selectTrip(name)` перезагружает базу, пока запись не идёт; выбор хранится в `SharedPreferences`.
  - `NavScreen` получает карту из каталога выбранной поездки.
  - Над кнопкой «Старт» — список поездок (только когда их больше одной и запись не идёт).
  - В заголовке журнала сессии — необязательное поле `trip`.

## Ошибки
- **Нет `trips/`** — старая раскладка.
- **Есть `trips/`, но поездок с `refpack.bin` нет** — статус «Нет поездок в trips/» и подсказка `adb push`.
- **Выбранной поездки больше нет** — берётся первая по алфавиту.
- **В каталоге поездки нет модели и нет `refpack/model.onnx`** — понятная ошибка «нет модели».

## Тестирование
- **pytest:**
  - отметка краёв (обрезанная линия → край, тупик → нет);
  - запись и чтение v3, v2 по-прежнему читается;
  - `--bbox` в `pack-roads`;
  - `pack-trip` с подменёнными шагами: раскладка, `trip.json`, перенос модели, конфликт моделей, `--force`, неверное имя.
- **Kotlin `:core`:**
  - разбор v3, фикстура v3 от Python;
  - Router: нет разворота у края, разворот в тупике сохранён, маршрута нет, если единственный путь — разворот у края.
- **Kotlin `:replay`:**
  - `trip-plan` на тестовом графе, в том числе via;
  - шаг точек GPX ≤ 25 м, время в каждой точке;
  - код 2 без дороги.
- **`:app` (JVM):** `TripLayout` — старая раскладка, список, выбор, исчезнувшая поездка, модель в корне и в поездке.

## Ограничения (в документацию)
- Промежуточные точки задают только коридор. На телефоне маршрут строится к финишу внутри коридора и может срезать мимо via.
- Граф города для `trip-plan` на Москву требует нескольких ГБ памяти JVM (`-Xmx4g`).
- Без интернета на телефоне; пакеты кладутся через adb.
